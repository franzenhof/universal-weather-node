# Building Your Own Display or App (HTTP API)

The JSON API for third-party displays, dashboards and apps: endpoints, units, optional fields, polling, history, CORS, discovery and the stability promise.

[← back to README](../README.md)

The node deliberately has no big display of its own. Instead it offers a small, stable, documented HTTP API in your LAN — build the display you want (an e-paper frame, a wall tablet, a phone widget, a Grafana-free kiosk page) against it.

| You need | Where |
|----------|-------|
| The machine-readable contract | [`openapi.yaml`](api/openapi.yaml) (OpenAPI 3.1) and the JSON Schemas [`data`](api/schemas/data.schema.json), [`history`](api/schemas/history.schema.json), [`info`](api/schemas/info.schema.json) |
| Real responses to develop against | [`docs/api/examples/`](api/examples/) — five setups, see [Example Responses](#example-responses) |
| A node on your desk without hardware | the [mock server](../tools/api-mock/README.md) |
| A template to start from | [`examples/simple-display/index.html`](../examples/simple-display/index.html) — one dependency-free HTML file |

**Viewing the OpenAPI file:** open it in the [Swagger Editor](https://editor.swagger.io) (File → Import), or run a viewer locally from the repository root so the relative schema references resolve, e.g. `npx @redocly/cli preview-docs docs/api/openapi.yaml` (Redoc) or `docker run -p 8081:8080 -e SWAGGER_JSON=/api/openapi.yaml -v "$PWD/docs/api:/api" swaggerapi/swagger-ui` (Swagger UI on port 8081).

## Quick Start

With Wi-Fi and the web API enabled (the default) the node answers on port 80 of its IP address — or by name, see [Discovery](#discovery-mdns):

```bash
curl http://garden.local/api/info      # what this node is and what it measures (read once)
curl http://garden.local/api/data      # the current values (changes once per measurement cycle)
curl "http://garden.local/api/history?range=24h"   # charts: 5-min buckets; range=7d: 1-h buckets
```

Or without hardware: `python3 tools/api-mock/mock_server.py` and use `http://localhost:8080`.

A minimal JavaScript client:

```js
const node = 'http://garden.local';
const info = await (await fetch(node + '/api/info')).json();
if (info.apiVersion !== 1) console.warn('unknown API version', info.apiVersion);
const d = await (await fetch(node + '/api/data')).json();
if ('temp' in d) show('Temperature', d.temp.toFixed(1) + ' °' + d.tempUnit);
if ('windSpeed' in d) show('Wind', d.windSpeed.toFixed(1) + ' ' + d.windUnit + ' ' + (d.windDirText || ''));
```

## Endpoints

| Endpoint | Auth | CORS | Content |
|----------|------|------|---------|
| `GET /api/info` | – | `*` | Device description: name, host name, firmware, board, units, outputs, available value groups, sources, cycle length, history ranges ([schema](api/schemas/info.schema.json)) |
| `GET /api/data` | – | `*` | Current measurement — the same JSON as the MQTT data topic ([schema](api/schemas/data.schema.json)) |
| `GET /api/history?range=24h` (or `7d`) | – | `*` | Bucketed history for charts, in RAM ([schema](api/schemas/history.schema.json)) |
| `OPTIONS` on the three above | – | `*` | CORS preflight (204) |
| `/api/settings`, `/api/log`, `/api/log/raw`, `/api/log/clear`, `/api/rf/trace`, `/api/davis/log` | Digest (`admin`) | none | Settings, log and [radio trace](wireless-sensors.md#capturing-a-radio-trace-for-us) for the owner — not for third-party UIs; POSTs are same-origin only |
| `/`, `/status`, `/help`, `/help.md` | – | none | The node's own pages |

All JSON is UTF-8 `application/json`, sent with chunked transfer encoding and `Cache-Control: no-store`. A JSON allocation failure (very low memory) answers `500` with a plain-text message — retry later. Unknown paths answer `404`. Details of every status code: [`openapi.yaml`](api/openapi.yaml).

## Fields, Units and Numbers

The schemas document every field with its type, range, unit and when it is present. The essentials:

**Absent means "not available" — never guess.** A value appears only while its sensor or function delivers it: no BME280 → no `pressureQnh`; clock not synced yet → no `rainToday`; less than about 3 h of uptime → no `pressureTrend3h`. Never treat a missing field as 0 and never keep showing the last value as if it were current — show "–" instead. `null` occurs only inside arrays (`ds18b20` slots, history buckets) and for `batteryVolt` on a failed reading.

**Units come from the data, not from assumptions.** Every value has either a fixed unit (documented as `x-unit`) or a sibling unit field (`x-unit-field`): `temp` + `tempUnit`, `windSpeed` + `windUnit`, `rain` + `rainUnit` … The unit fields exist only together with their values; `/api/info` → `units` lists all units unconditionally (use it e.g. for `rfSensors[].temp` when the node has no temperature source).

| Quantity | Metric | Imperial | Fields |
|----------|--------|----------|--------|
| Temperature | `C` | `F` | `temp`, `dewPoint`, `feelsLike`, `ds18b20[]`, `cpuTemp`, `rfSensors[].temp` |
| Temperature change | K | °F | `tempTrend1h` |
| Pressure | `hPa` | `inHg` | `pressureAbs`, `pressureQnh`, `pressureTrend3h` |
| Wind speed | `m/s` or `km/h` (setting) | `mph` | `windSpeed`, `windGust`, `wind2.*`, `rfSensors[].wind*` |
| Rain amount | `mm` | `in` | `rain`, `rainSinceStart`, `rain1h` … `rainYear`, history `rainMm` (in `in` when imperial, despite the name) |
| Rain rate | `mm/h` | `in/h` | `rainRate` |
| Cloud base | `m` | `ft` | `cloudBase` |
| Fixed | % · deg · lx · V · A · W · kWh · kPa · s · min · dBm | same | `humidityPct`, `windDirDeg`, `lightLux`, `batteryVolt`, `victron.*`, `vpd`, … |

The unit system is a device setting; if your UI has its own preference, convert from whatever the node sends (the built-in dashboard does the same).

**Numbers** are JSON numbers with up to about 7 significant digits (32-bit floats). Most are **not rounded** (`"windSpeed": 4.25097`) — round for display: one decimal for temperature, wind, rain (two for inches), humidity as integer, pressure one decimal in hPa / two in inHg. Pre-rounded: `dewPoint`, `feelsLike`, `tempTrend1h` (0.1), `vpd`, `pressureTrend3h` (0.01), `cloudBase`, `sunshine*Min`, `rfSensors[].lightLux` (integers). History values are stored compactly (wind/rain rate 0.01, temperature 0.1 °C, humidity 0.5 %, pressure 0.1 hPa) and converted on output.

**Text values are machine keys** in English (`windDirText` `"SW"`, `pressureTendency` `"falling slowly"`, `weatherTrend` `"improving"`, `resetReason`, `heater.mode`): translate them in your UI; the full lists are the `enum`s in the schema.

**Timestamps:** `/api/data` holds the values of the last *completed* cycle and has no timestamp of its own — the cycle ended about `measurement.cycleSec − nextCycleInSec` seconds ago (MQTT: at publish time). The only absolute time is `lastRain` (ISO 8601, UTC). History uses relative `ageSec`, so it does not depend on the node's clock. "Today" (`rainToday`, `sunshineTodayMin`) follows the device time zone (`/api/info` → `measurement.timeZone`) and exists only once the clock was synced (`measurement.clockSynced`).

**Wireless sensors:** `rfSensors[]` lists every received sensor (up to 32) with its *own* readings and its number `slot` (1–32: position in *Wireless sensor IDs*, else reception order; 1–4 are the value-source choices *Wireless 1–4*); the same object is published per sensor on the MQTT topic `<prefix>/rf/<id>`. `type` 3 covers the Bresser pool thermometer and the Fine Offset WN34 / WN38 probes — use `model` to tell them apart; the top-level values come from the sensor selected per group in `sources` (`"board"`, `"radio:<id>"` or `"none"`). For the main display use the top-level values; use `rfSensors[]` for extra tiles (a WH31 in the greenhouse, soil moisture). Fine Offset sensors add per-sensor values outside the value groups: `pm25`, `pm10` (+ `pm10Estimated`), `pm1`, `pm4` (µg/m³), `co2Ppm`, `externalPower`, `leak` / `leakHighSensitivity` / `leakRaw` (WH55), `leafWetnessPct` (WN35), `conductivityUsCm` (WH52) and `pressure` (WN32P, station pressure in `pressureUnit` of `/api/info` — not `pressureQnh`); they have no `stale` group, use `ageSec`. A value group listed in `stale` has not been received for 5 minutes. See [Value Sources](wireless-sensors.md#value-sources).

## Polling

The node is a microcontroller that serves one request at a time — be gentle:

1. Read `/api/info` once at start (again if `device.uptimeSec` went down: the node restarted, the history is gone).
2. Read `/api/data`; schedule the next read for `nextCycleInSec + 2` seconds (at least 5 s, at most `measurement.cycleSec`). `/api/data` does not change in between — faster polling only costs the node time.
3. Read `/api/history` after each new `/api/data` at most, typically every 5 min (`range=24h`) or hourly (`range=7d`) — the 24h document is about 20 KB.
4. On a network error, back off (e.g. 10 s, 30 s, 60 s) and keep showing the last values marked as old.

A handful of clients polling like this is no burden for the node; a client hammering `/api/history` every second is.

## History Ranges and Buckets

`/api/history` returns parallel arrays, oldest first. Element `i` of every value array belongs to `ageSec[i]`, the age of the end of bucket `i` at the time of the response — point `i` happened at *your request time − ageSec[i]*. The last element with `ageSec` 0 is the still-open bucket: a live preview of the current window.

| `range` | Nominal bucket | Buckets | Aggregation per bucket |
|---------|----------------|---------|------------------------|
| `24h` (default) | 5 min (`bucketSec` 300) | up to 288 + the open one | mean; `windGust` = maximum; `rainMm` = sum; `windDirDeg` = last valid value |
| `7d` | 1 h (`bucketSec` 3600) | up to 168 + the open one | same |

- `null` = no data in that bucket (sensor off or absent, or no cycle ended in that window). Draw a gap, not a 0. All arrays and unit fields are always present, even when every value is `null`.
- Buckets are fixed, back-to-back windows of `bucketSec` — on the wall clock (`:00`, `:05`, … UTC; full hours) once the node's clock is synced, on the uptime before that. A measurement cycle counts in the bucket in which it **ends**. There is one point per window, so 288 points are exactly 24 h and 168 exactly 7 days, and `ageSec` steps by `bucketSec` (one shorter step where the clock was first synced). With the default 300-s cycle every 5-min bucket holds one cycle; 60-s cycles give 5 per bucket; with cycles longer than the bucket (e.g. 600 s) the windows without a cycle are gaps (`null`), not filled in.
- The history lives in RAM and starts empty after every restart; long-term storage is MQTT's / Grafana's job.
- Rain totals: sum `rainMm` over the buckets you want. For "today" prefer `/api/data` `rainToday` (it survives restarts).

## CORS and Browsers

`/api/info`, `/api/data` and `/api/history` send `Access-Control-Allow-Origin: *`, so a page from **any origin** may read them — your UI does not need to be served by the node. An `OPTIONS` preflight is answered with `204` (also with `Access-Control-Allow-Private-Network: true` for Chrome's private-network checks). No credentials are involved; these endpoints never contain secrets.

The settings and log endpoints send no CORS headers and refuse cross-site POSTs — a third-party page cannot change the node's configuration.

**Mixed content:** the node speaks plain HTTP. A page loaded over **https** cannot fetch `http://` resources in current browsers. Serve your UI over http (any LAN web server, a Raspberry Pi, `python3 -m http.server`), open it as a local file, or package it as an app; a phone/desktop app (not a browser page) is not affected.

## Discovery (mDNS)

While Wi-Fi is connected and the web API is on, the node announces itself by multicast DNS:

| Record | Value |
|--------|-------|
| Host name | `<hostname>.local` — the device name in lower case, every other character run → `-`, at most 31 characters (`"Weather Mast"` → `weather-mast.local`); without a name `weathernode-<last 6 MAC hex digits>`. The same name is the node's Wi-Fi/DHCP hostname (router client list). Also in `/api/info` → `device.hostname` and on the status page |
| Services | `_http._tcp` and `_weathernode._tcp`, port 80, instance name = device name |
| TXT | `api=1` (apiVersion), `path=/api/info` |

```bash
dns-sd -B _weathernode._tcp              # macOS: list all nodes
avahi-browse -rt _weathernode._tcp       # Linux: list with addresses and TXT
```

Browse for `_weathernode._tcp` to find every node in the LAN, then read `http://<host>:<port><path>`. `.local` names work on macOS, iOS, Windows 10+ and most Linux desktops; Android resolves them in apps via NSD, browsers on older Android versions don't — fall back to the IP address (shown on the node's display and in your router). The host name changes only with the device name (applied at the next restart).

## Versioning and Stability

Every JSON document carries `"apiVersion": 1`, and the mDNS TXT record `api=1`.

- **Within apiVersion 1, fields are only added.** A new firmware may add fields and enum values (e.g. a new `resetReason` or sensor model) — ignore what you don't know, and render unknown enum values as text.
- **Renaming or removing a field, or changing its type, unit or meaning requires apiVersion 2.** Check `apiVersion` and warn on a version you were not written for.
- Which fields *appear* depends on the hardware and settings (see [Fields, Units and Numbers](#fields-units-and-numbers)) — that is not a contract change.
- The node's HTML pages (`/`, `/status`, `/api/settings`) are not part of the contract.

### Contract Test

`node --test test/api_contract.test.js` builds the real serializers for the host, regenerates the [example responses](#example-responses) for all five fixtures and fails if they differ from the committed files, if any document violates its schema, or if the firmware emits a key the schemas do not describe. After an intended change regenerate the examples with `UPDATE_API_EXAMPLES=1 node --test test/api_contract.test.js` and update the schemas and this page. See [Tests](development.md#tests).

## MQTT Equivalence

`/api/data` and the MQTT topic `<prefix>/data` are built by the same function and carry the same fields (including `apiVersion`), schema and units — a parser written for one works for the other. Differences: MQTT is pushed every MQTT interval instead of polled; its wind values may use the WMO 10-minute window (`/api/info` → `measurement.mqttWindAggregation`) and `rain` / `rainRate` refer to the MQTT interval. There is no MQTT equivalent of `/api/info` or `/api/history`. Topics and Home Assistant: [MQTT and Home Assistant](mqtt-home-assistant.md).

## UI Recipes

**Minimal display** — temperature, humidity, pressure with tendency, wind, rain today, warnings; [`examples/simple-display/index.html`](../examples/simple-display/index.html) is a complete, dependency-free version (about 110 lines) that works against a node and the mock server:

```js
const has = (d, k) => d[k] !== undefined && d[k] !== null;
const arrow = {rising: '↗', falling: '↘', steady: '→'};
function tendencyArrow(t) { return t ? arrow[t.split(' ')[0]] || '' : ''; }   // "falling slowly" -> ↘
const text = [
  has(d, 'temp') && `${d.temp.toFixed(1)} °${d.tempUnit}`,
  has(d, 'pressureQnh') && `${d.pressureQnh.toFixed(d.pressureUnit === 'inHg' ? 2 : 1)} ${d.pressureUnit} ${tendencyArrow(d.pressureTendency)}`,
  has(d, 'rainToday') && `${d.rainToday.toFixed(1)} ${d.rainUnit} today`,
  d.warnings && d.warnings.frost && 'FROST',
].filter(Boolean);
```

**Wind rose from the history** — 16 sectors, weighted by wind speed, last 24 h:

```js
const h = await (await fetch(node + '/api/history?range=24h')).json();
const rose = new Array(16).fill(0);
h.windDirDeg.forEach((dir, i) => {
  if (dir === null || h.windSpeed[i] === null) return;
  rose[Math.round(dir / 22.5) % 16] += h.windSpeed[i];
});
const total = rose.reduce((a, b) => a + b, 0) || 1;
const shares = rose.map((v) => v / total);   // 0 = N, 4 = E, 8 = S, 12 = W
```

**Rain bars per hour** — sum the bucket amounts by the hour they ended in:

```js
const now = Date.now();
const bars = new Map();   // hour start (ms) -> rain in h.rainUnit
h.rainMm.forEach((mm, i) => {
  if (mm === null) return;
  const t = now - h.ageSec[i] * 1000;
  const hour = t - (t % 3600000);
  bars.set(hour, (bars.get(hour) || 0) + mm);
});
```

**Trend arrows** — `tempTrend1h` (K or °F per hour) and `pressureTrend3h` are ready-made; `pressureTendency` / `weatherTrend` are classified texts. **Staleness** — mark the display old when your last successful `/api/data` is older than `measurement.cycleSec` + 60 s. **Sensor battery** — `radioBatteryLow` (a source sensor) or `rfSensors[].batteryOk`.
