# Troubleshooting

Symptoms and what to check first, plus the known limits of the current hardware and firmware.

[← back to README](../README.md)

Start with a short button press to view the display and `pio device monitor` for the serial log. With Wi-Fi/web API and an admin password configured, use **Status** and **Log** in the browser. Log messages and a complete measurement cycle are more useful than changing several settings at once.

| Symptom | Check first |
|---------|-------------|
| Nothing boots / USB not detected | USB data cable, stable power, correct serial port; on the V4 Full disconnect external supplies and remove JP8 before USB |
| Display says `cfgdata missing` | Perform a full [USB flash](development.md#build--flash) with the current partition table; OTA alone cannot fix it |
| Portal does not open | Hold the button for 3 s **after boot**, connect to `WeatherNode`, enter `http://192.168.4.1` in a normal browser; disable mobile-data/VPN routing if it interferes |
| No measurements sent yet | Wait one send interval (LoRaWAN, and MQTT by default: 300 s); check transport enable flags. An active portal pauses normal operation |
| LoRaWAN remains “not joined” | DevEUI/JoinEUI/AppKey, region, network profile and gateway coverage; inspect the logged error. Retries back off from 1 to 60 min (`retry in N min` in the log); a restart starts again at 1 min |
| Uplinks arrive, command does not run | Queue HEX `03` on **FPort 1**, wait for the next uplink; inspect gateway TX_ACK and device logs. FPort 0 traffic is MAC control, not this command; this firmware uses Class A |
| Wind/rain stays at zero | PCB detected (status page *PCB revision*: V4 Full / V4 Light), sensor enabled, numbered pinout, reed contact; debug log shows pulse counts |
| BME280 missing | Actual BME280 (not BMP280), 3.3 V supply, address 0x76 or 0x77, SDA/SCL wiring, cable length and pull-ups |
| DS18B20 missing / timeout | Three-wire VDD/GND/DQ wiring, 3.3 V supply, cable/contact faults; on the V4 Full / V4 Light power is switched only for conversions |
| Settings/Log cannot be opened | Enable Wi-Fi + web API and set an admin password (config portal or setup wizard); browser login user is `admin` |
| MQTT or weather uploads absent | Enable the service, verify credentials and network reachability; weather uploads also require NTP time. Broker TLS mode must match its listener |
| Heater/fan stays off | Correct supply and jumper, mode, first valid temperature in auto, VE.Direct battery/PV interlocks; entering the portal latches outputs off until restart |
| Wireless sensor not listed | *Wireless sensors* on, sensor within range (RSSI on the status page; above about −100 dBm is fine), not hidden (✕), and *Only my sensors* off or the sensor ★; only Bresser, TFA / LaCrosse IT+, Fine Offset (Ecowitt / Froggit) and — experimental, exclusive mode — Davis 868 MHz sensors are supported — *Wireless sensor type* must match (for IT+ try *both data rates*). *Paused for a LoRaWAN uplink* on the status page is normal |
| Wireless sensor not recognised, wrong values, received only sometimes | Capture a [radio trace](wireless-sensors.md#capturing-a-radio-trace-for-us) on the log page (`/api/log`) (*only unknown / failed packets*, or *only this ID*) and send us the downloaded file — it shows every packet the receiver got, also those that failed their checks |
| Status page *Clock* says *waiting for a time source*; weather uploads, records and history days are wrong | The node has no time. Wi-Fi without internet or a firewall that blocks **UDP 123** (NTP) is the usual reason: allow it, or set another *NTP server* (*Settings → Basics → Time*). Without internet other sources work: the dashboard open on a phone sets the time, a DCF77 radio-clock sensor (WH31 / WN31 DNT) or LoRaWAN network time — order and freshness: [Time sources](lorawan.md#time-sources-and-network-time-devicetimereq) |
| Wi-Fi `WeatherNode` is there, but I can't find the settings / which Wi-Fi is which | **`WeatherNode`** (no password, `http://192.168.4.1`) is the temporary **config portal** — only for the Wi-Fi network and a few basics; it opens by itself on a new node, later with the PRG button (3 s) ([Config Portal](installation.md#config-portal)). The node's **own access point** (`WeatherNode-XXXX`, with a password, for phones at a place without Wi-Fi) is a different thing: set up under *Settings → System → Own access point* in the web interface ([At the airfield](airfield.md)); it never offers the setup wizard and has no internet |
| Browser shows `401 Unauthorized` or keeps asking for the password | User is `admin` and the *web settings admin password*; with none set the settings and the log are disabled. After a *Reset settings* the admin password stays; after *Erase everything* there is none (a new node: set one in the setup wizard). Don't use the phone's small captive-portal sign-in window — open the address in a normal browser |
| `429 Too Many Requests` with a login | Too many wrong passwords from this address: every further try must wait 1 s, 2 s, 4 s … up to a minute (`Retry-After`). Wait, then log in with the right password; other devices are not affected ([Web Settings Page](settings.md#web-settings-page)) |
| Setup wizard comes again after every restart | It is offered after every restart until you finish it (**Finish**) or close it for good with **Later**; a reset (*Reset settings*, *Erase everything*) offers it again too ([Setup Wizard](installation.md#setup-wizard)) |
| No Home Assistant entities, or entities without values, for wireless values | MQTT on, broker reachable, discovery OK on the status page (*MQTT*). A wireless value group (wind, rain, UV …) is announced only **after a source has delivered it**: give the node a measurement cycle or two after a sensor was added. Details: [MQTT and Home Assistant](mqtt-home-assistant.md) |
| Status page / sensor list warns *two sensors are sending with this ID — values are mixed* (TFA / LaCrosse IT+) | IT+ has only 64 IDs, a neighbour's sensor sends under yours. Re-insert the battery of your own sensor (new ID) and mark it ★ again, or hide the neighbour's with ✕ / a *minimum signal per sensor* — see [Wireless Sensors](wireless-sensors.md#mine-received-hidden) |
| UV voltage or index is wrong | Correct J17 pin numbers, one sensor supply, JP10 and matching scale; a UV index additionally needs the sensor-specific transfer function and both calibration/index switches |

**Memory and HTTPS:** every HTTPS request (notifications, Weather Underground / Windy / openSenseMap, custom uploads to `https://`, the update check) needs about 45–55 KB of heap at its peak — the firmware's TLS library has fixed 16 KB receive and send buffers that cannot be made smaller with this toolchain. So a request only starts with at least **70 KiB free** in total and **24 KiB in one free block** (the two record buffers are separate ~16.7 KB allocations; the rest of the handshake comes in small pieces), and not while a settings, status, wizard or backup page is being built (it waits a few seconds); otherwise it is retried with a back-off. While one runs with less than 50 KiB free, those pages answer *busy, try again* (HTTP 503) for a moment. Plain HTTP uploads and MQTT without TLS are not affected. Watch `free`, `minimum` and `largest block` on the status page or in `/api/info` `system`; with *Debug mode* on, the log shows the heap before and after every HTTPS request.

**Known limits:** the V4 Full and V4 Light have not been qualified on real hardware. Current targets are not lightning/surge certification or guaranteed thermal ratings. An externally powered analog sensor can backfeed an unpowered controller; avoid powered signals with the node off. Chart history survives restarts and updates (saved every 30 min; a power cut loses at most the last 30 min), the rain statistics survive a power cut while *Keep rain statistics over a power cut* is on (default), and the AUX pulse total (RTC RAM) is lost on power loss. Keep the device on a trusted local network; the HTTP interface and the open config portal provide no encrypted configuration transport (the web interface can additionally be served over [HTTPS](settings.md#https)).
